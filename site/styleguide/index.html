Site style guide

The tokens and components this site is built from, with the rules for using them. Everything here lives in one stylesheet, /assets/site.css. The rules for writing tutorials are in TUTORIALS.md in the site repository.

Colour

The palette is a sunny street: white paper, sky blue sections, green for things that work, and the stop-paddle red only for something that is actually stopped. The fluorescent yellow-green always sits on or beside a dark border.

Rules

  • Say what was verified, on which versions, and when. If a claim can't be backed, weaken it or remove it.
  • Don't use absolutes such as tamper-proof, prevents all leaks or complete visibility. The site check rejects them unless they are quoted like this.
  • Use red only for stopped or unsupported states. The fluorescent yellow-green always has a dark border or dark text.
  • Don't use vendor logos or marks; write vendor names as plain text.
  • Don't load external fonts, scripts, images or analytics, and keep every page working without JavaScript.
  • The illustrative terminal window belongs on marketing pages. Tutorials use captioned code blocks and never show made-up output.
  • Write the product name as Crossing Guard in prose and crossing-guard as a command.
  • In tutorial prose, don't use dashes, not just X but Y contrasts, bold labels at the start of list items, or stock phrases such as here's the thing. The site check flags these; TUTORIALS.md explains the full voice rules.
