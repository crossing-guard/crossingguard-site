Release notes

What changed in the October 2026 source refresh

On October 7 we moved the public source from the September 25 snapshot to upstream revision 5607e508. Below is what changed, how we made the published tree, and where our checks stopped.

Published 2026-10-09 · Crossing Guard maintainers

Getting the public tree back in step

We had assembled the September snapshot by hand. It had drifted: several fixes lived only in the public copy, and newer upstream code no longer fitted it. Before the refresh, we ported those fixes upstream. For this release, we exported the upstream source folders directly and added the publication documents that live only in the public repository.

We also had some cleanup to do before the export. Upstream tests and help text used sample data from real work. We replaced it with neutral samples, along with ids captured from real sessions and comments citing unpublished design documents.

All of this arrived in one pull request. We kept the full record on the repository's refresh status page.

What changed since September

The database schema went from 32 in the September snapshot to 46. We also gave the lookup for an agent's executable one home, in internal/guardcli.

Recall tools now run over a local MCP server, started with crossing-guard mcp and registered with crossing-guard init --recall. The console gained per-call usage history read from local session files, session boards and model routes. We added an Antigravity transcript reader and Antigravity CLI chat through the same provider contract as the other agents.

The team server client arrived too, with crossing-guard link, a sync outbox and memory by scope. A linked device sends records to the team server named by its user; an unlinked device sends nothing to a team server. The server itself is a separate project and is not in the repository.

The safety-starter rulebook now has six rules. The new rule, team-link-change, asks before a device is linked to a team server.

Trying the upgrade from September

We seeded a store with the published September build: one rulebook selection, four observed tool calls, a session state and a checkpoint. Then we opened it with the refreshed build. It migrated the store from schema 32 to 46 and kept every seeded row. Running crossing-guard export wrote a schema-46 snapshot.

When we tried opening the upgraded store with the September build, it refused. Going back to an older build won't get you back into that store, so keep a copy of your data folder before you upgrade. Ours stayed readable at schema 32. The Data, export and recovery document has the details.

We tried this with one small store on a scratch home. This did not cover every older dataset.

The checks we ran

The hosted quality gate passed on the pull request, then again on main after the merge. It ran formatting, vet, the static checks, the browser test suites, the lints and the race tests. We also built the application and both analyzers from a clean checkout.

We started a daemon with a fresh home and no hooks installed. It answered doctor, init --dry-run, check and coverage. Over HTTP, we got 200 with its token and 401 with no token or a wrong one.

In the browser, Sessions and Governance loaded. Governance showed the seeded session and its four events. We tried a wrong key and got the not-connected screen; supplying the right key recovered the connection.

Where we stopped

We did not run a full installed journey on a clean macOS account: install, use with a real agent, recovery and uninstall. The checks above used disposable data. We did not check Linux or Windows either. macOS was the only platform we ran it on.

We ran our own scans for private names, sample data and captured session ids, with GitHub push protection still on. We did not run a dedicated secret scanner.

One bit of wording has not caught up with the change. crossing-guard init still prints "nothing leaves this machine" beside the data folder. That holds for an unlinked device, but we have not reworded it for a linked one.

We shipped source. There is still no binary download; Building the source lists what you need.
