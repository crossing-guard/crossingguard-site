What changed in the October 2026 source refresh

On October 7 the public source moved from the September 25 snapshot to upstream revision 5607e508. This post lists what is new, how the published tree is now made, what we checked and what we did not.

Published 2026-10-09 · Crossing Guard maintainers

How the published tree is made now

The September snapshot was assembled by hand, and it had drifted. Several fixes existed only in the public copy, and code written upstream since then no longer fitted it. Before this refresh we ported those fixes upstream. The public tree is now a direct export of the upstream source folders, plus the publication documents that live only in the public repository.

Tests and help text upstream used sample data taken from real work. We replaced it with neutral samples before the export, along with session ids that had been captured from real sessions and comments that cited unpublished design documents.

The change arrived as one pull request. The refresh status page in the repository has the full record.

What is new since September

  • The database schema is 46. The September snapshot was at 32.
  • Recall tools run over a local MCP server, started with crossing-guard mcp and registered with crossing-guard init --recall.
  • A team server client arrived: crossing-guard link, a sync outbox and memory by scope. A linked device sends records to the team server its user names. The server is a separate project and is not in the repository. An unlinked device sends nothing to a team server.
  • The console gained per-call usage history read from local session files, session boards and model routes.
  • There is an Antigravity transcript reader, and Antigravity CLI chat through the same provider contract as the other agents.
  • The safety-starter rulebook has six rules. The new one is team-link-change, which asks before a device is linked to a team server.
  • The lookup for an agent's executable has one home, in internal/guardcli.

Upgrading from the September build

We seeded a store with the published September build: one rulebook selection, four observed tool calls, a session state and a checkpoint. The refreshed build opened it and migrated it from schema 32 to 46 with every seeded row kept. crossing-guard export then wrote a schema-46 snapshot.

The September build refused to open the upgraded store. An older build is not a way back, so keep a copy of your data folder before you upgrade. The copy we kept stayed readable at schema 32. Data, export and recovery has the details.

This was one small store on a scratch home. It does not cover every older dataset.

What we checked

  • The hosted quality gate passed on the pull request and again on main after the merge. It runs formatting, vet, the static checks, the browser test suites, the lints and the race tests.
  • The application and both analyzers build from a clean checkout.
  • A daemon started with a fresh home and no hooks installed answered doctor, init --dry-run, check and coverage. Over HTTP it returned 200 with its token and 401 without one or with a wrong one.
  • In a browser, Sessions and Governance loaded, Governance showed the seeded session and its four events, a wrong key produced the not-connected screen, and the right key recovered.

What we did not check

  • A full installed journey on a clean macOS account: install, use with a real agent, recovery and uninstall. The checks above ran on disposable data.
  • A scan with a dedicated secret scanner. We ran our own scans for private names, sample data and captured session ids. GitHub push protection stayed on.
  • Linux and Windows. macOS is the only platform we run it on.

One sentence in the product is behind the change: crossing-guard init still prints "nothing leaves this machine" beside the data folder. That holds for an unlinked device and has not been reworded for a linked one.

This is still a source release. There is no binary download. Building the source lists what you need.
