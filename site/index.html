Open source, built in the open.

The framework source is on GitHub under the Apache 2.0 licence, and you build it yourself with Go. Crossing Guard runs every day on our own Claude Code, Codex and OpenCode sessions. OC OpenCode Deny on 1.18.0

One binary connects to each agent at its own extension point: hook entries for Claude Code, Codex and Cursor, and a plugin for OpenCode. Claude Code and Codex can allow a tool call, hold it for you, or deny it. Codex skips a hook until you trust it once in its /hooks screen. OpenCode blocks only on the version we verified (1.18.0) and records on any other. Cursor denies, and a rule that would ask is denied too. Read the installers →

A registered hook is not a firing hook. crossing-guard verify and doctor report the hook events they have seen on your machine.

What it does

01

One memory

Project memory is plain Markdown on your disk, one file per record, with no vendor store. Claude Code and Codex read the same files: a session-start hook adds the records for the repository you are in. See the store →

crossing-guard — memory
crossing-guard attach claudecrossing-guard attach codexls ~/.crossing-guard/memory api-retry-policy.md release-checklist.md recall-log.jsonl (file names are examples)
rules.safety-starter.json — one rule
{ "id": "git-force-push", "action": "ask", "message": "force push can discard published history for everyone", "backstop": "remote-branch-protection", "if": { "tag": "command", "matches": "\\bgit\\s+push\\b.*(--force\\b|…)" }}

02

One rulebook

A rule is JSON: an id, an action and a condition. The actions are deny, ask, allow, observe and redact. A fresh install selects no rules. Opt in to the six starter rules with crossing-guard rules select safety-starter, or point it at your own file. Command matching is best-effort, so keep your branch protection. Read the starter rules →

03

Every agent, one file

The same rule document is evaluated for every connected agent, by one evaluator. crossing-guard check shows what a command would get before any agent tries it. This output is from a build of the published source with the starter rules.

crossing-guard check — dry run
crossing-guard check "git push --force origin main"ASK git-force-push "git push --force origin main"crossing-guard check "git status"allow (no rule matched) "git status"

How it works

1

Build & connect

Build the binary from source. crossing-guard init --dry-run lists every change first, and init then asks per agent before it writes a hook.

2

Pick your rules

Select the starter rules or your own JSON file. Nothing is asked or denied until you do.

3

Watch it work

crossing-guard console opens the local console: Sessions, Memory, Skills and Governance, with approvals waiting for you.

build from source — Go 1.26 or later, macOS
git clone https://github.com/crossing-guard/crossing-guardcd crossing-guardgo build -mod=readonly -o bin/crossing-guard ./cmd/crossing-guard./bin/crossing-guard init --dry-run
